# ADR-0002. Поставщик LLM и какие данные ему уходят

**Статус.**
- Пункты 1–3 и 5 — **принято**: направление тимлида в ревью `65fa311` (2026-09-27) и решение владельца проекта на тестовый период (2026-10-17, карточка S2-04).
- Пункт 4 — **принято**: владелец 19.10 по сравнению S2-05 на eval-наборе (`docs/eval/models-2026-10-19.md`).

Прежняя версия этого ADR в ветке `claude/H-01-H-11-hunter-v0` называла поставщиком Anthropic Claude со статусом «принято командой». Это было решение автора, а не команды, поэтому в `main` она не переносится (журнал, «Ошибки и выводы»).

## Решение

### 1. Один OpenAI-совместимый адаптер (принято)

`infrastructure/llm/openai_compatible.py` говорит с любым поставщиком, который принимает `POST {base_url}/chat/completions`:
- OpenRouter — на тестовый период;
- локальный сервер open-source модели — для разработки (`http://127.0.0.1…`, ключ не нужен);
- polza.ai — для research (пункт 4).

Порядок: сначала open-source модели, затем сравнение с polza.ai на eval-наборе — сделано 19.10, итог в пункте 4. Gemini не используем. Адаптеры Claude и Gemini и зависимость `anthropic` в `main` не идут. Новых зависимостей нет: HTTP — стандартная библиотека.

### 2. Тестовый период — бесплатные open-source модели через OpenRouter (принято, владелец 17.10)

- Только open-source модели с пометкой `:free` (Qwen, DeepSeek, Llama и т. п.). На `openrouter.ai` модель без `:free` — ошибка конфигурации (код 2). Модель, в имени которой есть `gemini`, — тоже.
- У ключа лимит расходов 0. Бесплатный суточный лимит запросов мал: его хватает на eval и отладку, на пилот — нет.
- Ключ — только в переменной окружения процесса `HUNTER_LLM_API_KEY`. Адаптер не выполняет HTTP-редиректы: `urllib` иначе переносит заголовок `Authorization` на любой адрес из `Location` (ревью #13). Ответ `3xx` — ошибка `unknown`, без повтора. В `.env`, репозитории, карточках, логах и чатах его нет: если он найден в `.env`, запуск останавливается с ошибкой конфигурации. Ключ у владельца, он его меняет.

### 3. Какие данные уходят модели (принято, владелец 17.10)

- **Только публичные данные компаний и синтетические карточки eval-набора.** Бесплатные поставщики могут логировать запросы и учиться на них. Имена, почты и телефоны людей не отправляются. Для пилота с живыми лидами поставщик выбирается отдельно (пункт 4).
- **Контакты маскируются перед любым вызовом** (`application/llm_privacy.py`, `MaskingClient`). Каждый клиент модели в `runtime` обёрнут в маскировку, поэтому её не обойти забывчивым сценарием. Маскируются e-mail, в том числе записанные как `[at]`, `(at)` или «собака», телефоны, Telegram и WhatsApp, страницы в соцсетях (`vk.com`, `ok.ru`, `instagram.com`, `facebook.com`, `tenchat.ru`, `linkedin.com/in`). ИНН, ОГРН и суммы, записанные группами по три цифры, остаются: это публичные данные компании, нужные исследованию.

### 4. Модель для research (принято, владелец 19.10)

| | Модель polza.ai | Eval, промпт v3 | ₽ за карточку |
| --- | --- | --- | --- |
| Основная | `deepseek/deepseek-v4.1-flash-1017` | 27 из 30 | 0.13 |
| Запасная | `openai/gpt-6-luna` | 25 из 30 | 0.075 |

- Поставщик — polza.ai, `HUNTER_LLM_BASE_URL=https://api.polza.ai/api/v1`, цены — `HUNTER_LLM_PRICE_*` (пункт 5), строгая схема (`json_schema`).
- Запасная модель включается вручную, сменой `HUNTER_LLM_MODEL`, если основная недоступна или её качество на eval упало. Автоматического переключения нет.
- Лимит ответа research — 8000 токенов: думающие модели с лимитом 3000 обрезались (документ 12, `RESEARCH_MAX_OUTPUT_TOKENS`).
- Выбор по сравнению четырёх моделей на одном наборе, разметке и лимите: DeepSeek лучший по качеству и в 10 раз дешевле Gemini 4 Argon (25 из 30, 1.38 ₽); Claude Haiku 5.5 — 23 из 30.
- Gemini в коде по-прежнему запрещён: Argon гонялся один раз для сравнения по просьбе владельца, из копии кода вне репозитория.
- 152-ФЗ и хранение данных в РФ на тестовом этапе не учитываются (владелец, 19.10): обе модели обрабатывают данные вне РФ. Правило пункта 3 действует: модели уходят только публичные данные компаний, контакты маскируются. Перед пилотом с живыми лидами вопрос поднимается снова.

### 5. Тариф и лимит затрат обязательны (принято)

Документ 09: если тариф неизвестен, платный вызов не начинается.
- У модели `:free` тариф — 0 в валюте учёта.
- Для другой модели нужны обе цены: `HUNTER_LLM_PRICE_INPUT_PER_M` и `HUNTER_LLM_PRICE_OUTPUT_PER_M`, за миллион токенов. Без них тариф неизвестен (`None`), и бюджет S2-07 не начнёт платный вызов.

В каждом результате вызова есть расход токенов и стоимость (S2-01), включая неудачные вызовы.

Лимиты затрат (владелец, 23.10; документ 12, проверяет S2-07):
- `RUN_COST_CAP` — 2 ₽ на один запуск research. Карточка на DeepSeek стоит около 0.13 ₽, с исправлением формата — около 0.3 ₽: запас примерно в шесть раз, сломанный запуск много не сожжёт.
- `DAILY_COST_CAP` — 200 ₽ в день на все вызовы модели. Дневной лимит сверяется со списанием поставщика, а не только с суммой `LlmResult.cost`: 19.10 polza списала около 200 ₽ при сумме по отчётам около 70 ₽ — запросы, ответ на которые не дошёл, похоже, тоже оплачиваются.
- `COST_CURRENCY` — RUB.

### Что повторяет очередь (S2-06)

| Исход | Код | Повтор |
| --- | --- | --- |
| Таймаут транспорта, 408, 504 | `timeout` | да |
| 429 | `rate_limited`, с `retry_after_s` | да |
| 5xx, недоступность, страница шлюза вместо JSON, `finish_reason=error` | `unavailable` | да |
| 401 / 402 / 403 | `auth` / `quota` / `refusal` | нет |
| 400, 413, 422 | `bad_request` | нет |
| Обрезанный ответ, не JSON | `truncated`, `not_json` | нет: исправление формата — новый запрос |
| Изменённая форма ответа, редирект, прочее | `unknown` | нет |

## Как проверить подключение

Владелец запускает своим ключом:

```bash
export HUNTER_LLM_BASE_URL=https://api.polza.ai/api/v1
export HUNTER_LLM_MODEL=deepseek/deepseek-v4.1-flash-1017
export HUNTER_LLM_PRICE_INPUT_PER_M=9.36 HUNTER_LLM_PRICE_OUTPUT_PER_M=28.07
export HUNTER_LLM_API_KEY=…                  # только в окружении
python -m hunter llm-check
```

На тестовом периоде OpenRouter: `HUNTER_LLM_MODEL=qwen/qwen3-8b:free` без цен и `HUNTER_LLM_BASE_URL`.

Команда отправляет одну синтетическую карточку без данных о реальных компаниях и людях. Она печатает модель, статус, токены и стоимость — ключ и текст поставщика не печатаются. Если модель не поддерживает строгую схему, задайте `HUNTER_LLM_STRUCTURED=json_object`.
