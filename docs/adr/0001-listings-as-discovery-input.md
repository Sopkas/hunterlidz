# ADR-0001. Объявления площадок как вход Discovery

**Статус:** предложено — требуется решение PM (не принято).
**Дата:** 2026-09-27. **Автор:** ИИ-агент по заданию пользователя.

## Контекст

Спецификация (doc 08, FR-01; doc 03) строится на компаниях: вход — «company name, website или source URL», источник — сайт, новости, вакансии. Пользователь поставил задачу «загрузить 100–200 объявлений с одной площадки и отобрать лиды». В прототипе это было реализовано молча, без решения PM; ревьюер справедливо отметил это как смену предмета продукта.

## Решение (предлагаемое)

Объявление — это **источник** (`sources.source_type = listing`) и набор **evidence** для компании, а не новая сущность продукта. Модель данных остаётся из doc 10: companies → leads → evidence / sources.

- Строка с названием компании и сайтом без текста объявления импортируется как обычная компания FR-01 (research читает сайт).
- Строка-объявление создаёт компанию (без домена — не склеивается по имени, T-02), источник со снимком текста и evidence по полям.
- Отсев мусора и предварительный score применяются к тексту объявления; итоговый score doc 04 — по evidence, как для любого источника.

## Последствия

- Объявление с площадки — это «запрос исполнителя»; doc 03 считает такой запрос сигналом текущей потребности. Нужно подтверждение PM, что это допустимый сигнал для outreach и что условия площадки разрешают использовать данные.
- Компании без сайта не объединяются автоматически: один заказчик с двумя объявлениями даст два лида до ручного слияния.
- Если PM отклонит решение, импорт объявлений отключается без изменения модели данных: остаётся импорт компаний FR-01.
