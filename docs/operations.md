# Эксплуатация Hunter v0

Основа — doc 12 «Telegram и эксплуатация». Интерфейс v0 — CLI; Telegram-панель (H-08) подключается к тем же сценариям позже.

## Режимы

| Режим | Что можно | Кто переключает |
| --- | --- | --- |
| `shadow` (по умолчанию) | импорт, research, scoring, черновики, согласование; регистрация отправки запрещена | admin |
| `manual` | всё из shadow + регистрация реальной ручной отправки | admin |
| `paused` | только чтение, запись ответов и запреты контакта | admin |

```bash
python -m hunter mode paused --reason "инцидент: ошибки провайдера"
```

Переключение пишется в аудит (`hunter history run_mode`).

## Планировщик

`python -m hunter tick` раз в минуту. Он ничего не отправляет: отмечает наступившие задачи, сворачивает пропущенные после простоя касания в одну задачу «проверить актуальность», показывает возвраты из NURTURE.

- Linux / macOS (cron): `* * * * * cd /srv/hunter && .venv/bin/python -m hunter tick >> logs/tick.log 2>&1`
- Windows: Планировщик заданий → «Создать задачу» → триггер «каждую 1 минуту» → действие `py -m hunter tick`, рабочая папка — корень репозитория.

`.env` с `HUNTER_ACTOR` должен лежать в рабочей папке задачи.

## Резервные копии

Ежедневно (doc 12: хранение 30 дней, RPO 24 ч, RTO 4 ч — цели, принимаются после проверки восстановления на staging):

```bash
python -m hunter backup                     # backups/hunter-YYYYMMDDTHHMMSSZ.db
python -m hunter restore backups/<файл>.db --yes
```

Восстановление повторно применяет запреты контакта, созданные после копии, проверяет целостность и внешние ключи и печатает количество компаний, лидов, сообщений, запретов и событий аудита для сверки. Папка `backups/` в `.gitignore`: копии содержат данные лидов.

## Сбои (runbook doc 12)

| Событие | Что делать |
| --- | --- |
| LLM недоступен / квота | Research завершится `failed` с кодом (`quota`, `unavailable`); очередь и данные сохранены. Повторить позже `hunter research`. При повторяющихся ошибках — `mode paused`. |
| Бюджет исчерпан | Статус `budget_exceeded`; дневной лимит `DAILY_COST_CAP` сбрасывается в начале делового дня. |
| Источник недоступен | Сохраняется с кодом ошибки (`hunter lead <ID>`), факт не выдумывается. |
| Ошибочный кейс в сообщении | Исправить `data/case_claims.json` → `hunter claims load` (новая версия утверждения); неотправленные черновики проверить через `hunter review`. |
| Запрет контакта | `hunter suppress …` отменяет задачи и неотправленные сообщения; снимает только admin с основанием. |
| Утечка ключа | Отозвать ключ у провайдера, выпустить новый, заменить в `.env`; ключ не пересылать в чат. |
| Ошибка после обновления | `mode paused`, откатить код; миграции откатываются только по проверенному плану. |

## Секреты

Только в `.env` (в `.gitignore`), у каждого разработчика свои ключи. В логах, журнале, аудите и экспорте ключей нет; экспорт контактов — только с `--with-contacts` и хранится как данные клиентов.
