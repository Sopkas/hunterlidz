# Инструкции для ИИ-агентов

Агент работает по правилам «Как мы работаем» так же, как человек. Кратко:

1. Задачи — только карточки YouGile (проект HunterLidz), ID вида `S1-03` из `docs/roadmap.md`. Задачу назначает человек; агент называет её и ждёт явного «да».
2. Ветка: `claude/<ID>-<slug>`, например `claude/S1-03-package-skeleton`, от свежего `main` или от ветки предыдущей задачи стека (`docs/roadmap.md`).
3. Коммиты: английский, повелительное наклонение, до ~72 символов, ID в скобках: `Add package skeleton (S1-03)`. Тело — Why / What / Not doing. Трейлер `Co-Authored-By: <модель> <noreply@…>`.
4. Перед PR локально: `python -m pytest -q --durations=5`, `ruff check src tests`, `ruff format --check src tests`.
5. Журнал `PROJECT_STATUS.md` и `docs/` обновляются в том же PR.
6. Только по явной команде человека: push, создание PR, комментарии, merge, удаление веток. Merge решают люди.
7. Никогда: ключи в файлах, коммитах, логах, журнале; `push --force`; `rebase` общих веток; «тесты прошли» вместо «работает в проде».
8. Решения вне спецификации (поставщик, хранилище, предмет продукта) — только через ADR со статусом «предложено» и решение PM. Своё решение не записывается как решение команды.

## Что агенту трогать нельзя

- `.env` и любые файлы с ключами.
- `documents/` — база знаний команды, правит только владелец документа.
- Историю `main` и ветку-источник `claude/H-01-H-11-hunter-v0`.
