# Журнал Hunter

## Что уже есть

- Каркас пакета `src/hunter` по слоям domain / application / infrastructure / presentation / runtime.
- Конфигурация из `.env` и окружения; без `HUNTER_ACTOR` запуск завершается с кодом 2 до сетевых вызовов.
- Роли и матрица прав (doc 08 §3, doc 09).
- CI: Ubuntu 3.12 и 3.14, Windows 3.13; pip check, ruff, pytest без сети и ключей, smoke с кодом 2.
- SQLite-хранилище: миграции по номерам (повторный запуск — no-op), транзакции `BEGIN IMMEDIATE`, append-only аудит (триггеры запрещают UPDATE/DELETE).
- Пользователи и роли в базе, первый администратор через `hunter init`; режимы shadow / manual / paused с аудитом смены.
- Импорт CSV/JSON (FR-01/02): результат created / matched / rejected с причиной по каждой строке; повторный импорт не создаёт записей; компании без домена не объединяются по имени (T-02).
- Отсев мусора (`SCREENING_VERSION` 1.0) и предварительный score по ключевым словам (`PRESCORE_VERSION` 1.0) — только для ранжирования перед AI, это не score по doc 04.
- Объявление хранится как источник со снимком текста; каждое заполненное поле — evidence с цитатой.
- Безопасное чтение сайта компании (FR-03, T-09): только http/https, DNS-проверка всех адресов, соединение с проверенным IP (защита от DNS rebinding), повторная проверка каждого редиректа, лимиты 15 с / 1 МБ / text/html|plain; сбой хранится с кодом ошибки.
- Реестр кейсов (doc 01): версии утверждений, статусы owner_reported / verified / planned / withdrawn; `data/case_claims.json` — 4 утверждения из doc 01, загружает администратор.
- Проверка «запланированное ≠ готовое» для помощника претензионщика (T-07) — по предложениям о нашем опыте.
- База знаний: документы команды по номеру (`01-*.md` …) из `HUNTER_KNOWLEDGE_DIR`.
- AI research (H-05): адаптеры Gemini (stdlib) и Claude (SDK); контекст по doc 09 — инструкция doc 11 дословно, документы 01–03, реестр кейсов, задача, evidence в блоке недоверенных данных; бюджет doc 09 с резервированием до вызова; одна правка формата; повтор временных ошибок в пределах бюджета; очередь с lease, результат не пишется при потерянном lease; сохранённый результат не пересчитывается.
- Контракт research_v1.1 = research_v1 + offer (что продаём и почему) — `docs/research-contract.md`.
- Score по doc 04 (`RULES_VERSION` 1.0) считает код из проверенных признаков; таблица `scores` с CHECK на уровне БД (компоненты из допустимых уровней, сумма = total); каждая версия score хранится. После research лид переходит NEW → RESEARCHED при наличии фактов и гипотезы.
- Готовность к очереди сообщений (FR-06) считается на момент запроса: score ≥ 80, подтверждённый контакт, факт для персонализации, оффер, нет запрета; WARM и research с замечаниями — только по записанному исключению оператора; WATCH / SKIP — никогда.
- Прототип в `hunter/` (один файл) остаётся до H-11 как справочный; новый код его не использует.

## Важные решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-27 | Python ≥ 3.12, stdlib `sqlite3` без ORM | Меньше зависимостей; новые зависимости — через координатора зоны A |
| 2026-09-27 | Часовой пояс — фиксированное смещение `HUNTER_BUSINESS_UTC_OFFSET` | `zoneinfo` на Windows требует пакет `tzdata` |
| 2026-09-27 | Компания определяется по нормализованному хосту, без склейки поддоменов | Для регистрируемого домена нужен список публичных суффиксов (doc 03) — новая зависимость через координатора; до этого лучше недообъединить, чем склеить разные организации |
| 2026-09-27 | Предварительный score отделён от score doc 04 | Ранжирование до AI не должно выдаваться за итоговую оценку на подтверждённых признаках |
| 2026-09-27 | Утверждения кейсов из doc 01 загружены как `external_allowed` с `approved_by = doc01-v1` | В doc 05 шаблоны уже используют CareerMate и CRM для автобизнеса как proof; окончательное разрешение — за PM (открытый вопрос) |
| 2026-09-27 | Повторы LLM решает сценарий, а не адаптер; неудачная попытка считается вызовом | Все попытки укладываются в лимит 3 вызовов doc 09 |
| 2026-09-27 | Оценка токенов до вызова — символы / 3 (допущение) | Для резерва бюджета; фактический usage берётся из ответа провайдера |
| 2026-09-27 | Contactability выводится из сохранённых контактов, а не из ответа модели | Контакт — факт базы; расхождение с моделью записывается как противоречие |
| 2026-09-27 | Документы команды читаются из `HUNTER_KNOWLEDGE_DIR`, в репозиторий не входят | Репозиторий публичный; документы содержат цены и стратегию |
| 2026-09-27 | Интерфейс оператора v0 — CLI | Telegram (H-08) и HTTP API подключаются к тем же сценариям позже |
